# 搜索与来源选择

## 从问题和客户扩展候选

发现模式先覆盖多个客户/工作类型，再沿有证据的方向深入。不要只搜索“best micro SaaS”或反复列举知名成功案例。可从电商运营、代理机构、招聘运营、开发运维、财务行政、专业服务等切入；行业选择由实际线索决定，不机械遍历。

可组合的英文查询：

- `"<role>" "<repetitive task>" software pricing`
- `"<workflow>" "spreadsheet" "manual"`
- `"<product>" pricing` / `"<product>" changelog` / `"<product>" alternatives`
- `"<product>" "too expensive"` / `"<product>" "missing"`
- `"<product>" founder revenue` / `"<product>" open startup`
- `"<platform>" "<problem>" app`

把发现搜索与证据搜索分开：目录找到名字之后，访问该产品自身页面以及具体用户讨论。输入中指定的日期、行业、预算或排除项应进入查询和筛选；默认英语市场并不要求创始人或公司位于英语国家。

## 来源按用途使用

| 来源 | 用途 | 核验边界 |
| --- | --- | --- |
| 产品官网、文档、定价、更新日志 | 功能、价格、目标客户、最近公开活动 | 营销陈述要注明；网页能打开不等于产品正常运行 |
| 创始人博客、公开经营记录 | 创业路径、团队、获客、历史经营指标 | 自报收入保留原始时期、币种、口径，不能升级为审计数据 |
| 用户评论、社区讨论、评价平台 | 具体工作、付费经历、不满和替代方案 | 区分独立用户与官方收录证言、推广帖；单条抱怨不代表普遍需求 |
| Product Hunt、Indie Hackers、Show HN、生态应用目录 | 发现候选、定位发布者和初始反馈 | 排名、点赞、评论数不等于收入或留存 |
| 第三方访谈、收入榜单、收购目录 | 扩展线索和交叉核验 | 回到原始披露；榜单可能过期，目录挂牌不是成交记录 |

以上是来源类别示例，不保证任何网站当前可访问、有免费 API 或允许批量采集。使用时核对真实页面和工具能力；无需账号的公开资料优先。登录或付费墙后的数据不可见时写“未核验”，不绕过限制。

## 当前性与证据记录

- 每个来源保存 URL、标题、角色、访问日期、发布日期（未知填 null）以及访问状态。只看搜索摘要尚未打开正文的页面不能作为已核验来源；可保留为待访问线索。
- 每个关键事实明确对应来源，并记录数字的所属时期。今天读到 2023 年收入不能称为当前收入；历史披露可说明曾有商业验证。
- 官网价格记录货币、月付/年付周期、按量限额、试用与正式价格的区别。不能把年付折算月价当作可月付价格。
- 对近期停运、收购、转型或域名变化查公告、更新日志及当前入口；没有公告或近况只表示未知。第三方同名企业必须按域名与产品功能消歧。
- 官网收录的客户证言可支持“官方展示了该证言”，不是独立访谈。若以此推断需求，在结论里写明证据性质。
- 跨语言、平台或客户类型发现的案例，需要重新解释英语目标客户的支付、获客与交付条件，不能默认迁移成立。

每个最终推荐优先具备官网/定价来源和具体需求来源。两页来自同一公司仍属同一利益相关方；来源不足降低可信度。原始资料相互矛盾时并列陈述、说明时间差或口径差，无法解释则标记待验证。

## 一轮执行验收

核对：是否真实执行搜索和页面访问；候选是否有去重与取舍记录；至少有没有具体付费者、需求线索及可触达渠道；有没有把历史收入、官方营销或假设误写成当前已验证事实。小规模试跑可缩减候选数，但必须保留这些边界，并标记 `smoke-test`。
